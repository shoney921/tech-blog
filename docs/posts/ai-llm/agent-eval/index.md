# 에이전트 평가, 만져 보며

에이전트를 만들다 보면 숫자가 계속 나온다. 통과율 82%, 판정자 일치율 90%, 검증기 재현율 95%. 그런데 이 숫자를 보고 "그래서 배포해도 되나?"에 답하려면, 숫자가 어떻게 움직이는지 감이 있어야 한다. 공식을 외우는 것보다 슬라이더를 한 번 끝까지 밀어 보는 게 빠를 때가 많다.

그래서 각 편마다 직접 만질 수 있는 위젯을 하나씩 넣었다. 대상 독자는 에이전트를 실제로 만들고 있거나 만들려는 개발자다.

1. **오차 막대** — 평가셋 50개로 82% vs 78%가 나왔다. 정말 이긴 건가
2. **LLM 판정자** — 사람과 90% 일치한다는 판정자를 믿어도 되나
3. **검증기 문턱값** — 정밀도·재현율이 아니라 비용으로 문턱값 정하기
4. **검증과 재시도** — 단계마다 검증을 붙이면 끝까지 성공률은 얼마나 오르고, 비용은 얼마나 드나

먼저 [Pass@k와 Pass^k, 슬라이더로 직접 만져 보기](/posts/ai-llm/2026-10-12-pass-at-k-vs-pass-power-k)를 읽고 오면 4편이 더 잘 읽힌다. 평가셋을 어떻게 만들고 트레이싱을 어떻게 붙이는지는 [AI 연재 2/9](/posts/ai-llm/ai-systems/2026-10-04-ai-pipeline-02-evals-observability)에서 다뤘으니, 여기서는 나온 숫자를 읽는 쪽에 집중한다.
