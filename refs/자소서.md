[비정형 대화 서비스를 다중 사용자 프로덕션 시스템으로 전환]
 기존 Custom GPTs로 운영되던 대화형 진단 서비스를 다수 사용자가 이용하는 프로덕션 웹 앱('CEO AX Diagnosis Assistant')으로 재구현하는 과제를 수행했습니다. 목적은 비정형 대화 흐름의 구조화와 LLM 품질 및 운영 안정성의 동시 확보였습니다.
 요구사항 분석부터 아키텍처 설계, 풀스택 개발 및 운영까지 전 주기를 주도한 핵심 개발자로 참여해 대화 상태기계 엔진, LLM 연동 레이어, 데이터 파이프라인 설계를 담당했습니다. 백엔드는 FastAPI(async SQLAlchemy)와 프론트엔드는 React를 활용하고, LLM은 Azure OpenAI를, 인프라는 Docker/PostgreSQL로 구축했습니다. 또한 Neo4j 기반 GraphRAG와 Elasticsearch 기반 하이브리드 검색 파이프라인을 구축한 경험이 있습니다.
 진단 엔진을 '결정적 상태기계'로 두고 LLM을 '콘텐츠 생성 레이어'로 분리했습니다. 매 턴 구조화된 Envelope(메시지, 동적 선택지, 단계 상태, 슬롯 평가)를 생성하고, 답변이 빈약할 경우 부족한 축만 재질의하는 Probe 로직을 구현했습니다. 아울러 'LLM 우선 + 실패 시 규칙 기반 폴백'을 적용해 외부 의존성 장애가 전체 흐름을 끊지 않도록 방어벽을 설계했습니다.
 검색 고도화 측면에서는 Neo4j 기반 GraphRAG를 도입해 관계형 컨텍스트 기반으로 Retrieval 구조를 재설계하고 인덱싱과 질의 경로를 최적화했습니다. 또한 장문 필드를 청크로 분할해 키워드와 시멘틱을 결합한 하이브리드 검색으로 정확도를 높였고, LLM 요약 배치는 캐싱과 병목 구간 분석으로 처리 속도를 약 30% 이상 개선했습니다.
 20명 동시 접속 시 발생한 이미지 생성 API 429 에러와 큐 적체는 어드민 모니터링으로 원인을 실측했습니다. 동시성 제한 조정, 라운드로빈 우선순위 큐를 통한 버스트 평탄화, Retry-After 기반 재시도와 선생성(Pre-commit) 토글을 도입해 안정화했습니다. 결과적으로 비정형 서비스를 프로덕션 시스템으로 전환하고, 외부 AI 장애 시에도 100% 완주하는 안정성과 함께 현업 업무 시간을 대폭 단축했습니다.
[Microsoft Azure 기반 생성형 AI 서비스 구축]
 Microsoft Azure 환경을 기반으로 생성형 AI 서비스를 구성하고 안정적으로 운영한 경험이 있습니다. LLM 추론은 Azure OpenAI Service를 활용하되, 애플리케이션 서버, 데이터베이스, 컨테이너 런타임을 클라우드 상에서 통합 운영하는 아키텍처를 설계했습니다. 대화형 진단 어시스턴트, GraphRAG 지식검색, 성적서 검색·요약 자동화 등 복수의 AI 서비스를 대상으로 전용 서버 환경을 구축했습니다.
 Azure OpenAI를 Chat용과 이미지 생성용 리소스로 물리적 분리하여 트래픽 성격과 쿼터를 독립적으로 관리했습니다. 또한, 어드민에서 런타임에 LLM과 이미지 모델을 전환할 수 있는 모델 스위처를 구현해 코드 수정 없이 즉각적인 교체와 A/B 비교가 가능하도록 했습니다. GPU 및 API 자원이 소모되는 워크로드에 대해서는 배치 처리 시점을 분산하고 동시 호출 수를 자원 한계에 맞춰 제어하여 추론 병목과 과금 리스크를 동시에 방어했습니다.
 백엔드는 FastAPI(async) 기반의 비동기 API 서버를 개발하여 LLM 호출을 Async I/O로 처리함으로써 동시 요청 대기 시간을 최소화했습니다. JWT 인증과 전화번호 Allowlist 기반의 접근 통제를 적용해 보안성을 높였고, LLM·이미지 생성·검색·요약 등 외부 연동 로직을 재사용 가능한 서비스 계층으로 모듈화하여 확장성과 유지보수성을 확보했습니다.
 다중 사용자 동시 접속 환경의 성능 병목을 정량 진단하기 위해 가상 사용자 동시 요청 기반의 부하 테스트 도구를 직접 구현했습니다. 이를 통해 큐 적체와 429 에러를 관찰하고, 이미지 생성 동시성 파라미터, DB 커넥션 풀, 우선순위 큐 정렬 기준을 세밀하게 튜닝했습니다. 아울러 .env 기반의 런타임 노브(선생성 토글, 동시성 제어 등)를 도입해 재배포 없이 유연한 실시간 부하 대응 체계를 마련했습니다.
 로컬 개발 환경과 nginx 정적 빌드가 적용된 운영 배포 환경을 2벌의 Docker-compose로 표준화하여 배포 안정성을 높였습니다. 외부 AI 서비스 장애 시 규칙 기반 폴백 메커니즘으로 서비스를 중단 없이 이중화했으며, 개인정보 익명화 배치 작업을 자동 스케줄러로 운영해 컴플라이언스를 준수했습니다. 이를 통해 클라우드 환경 내 AI 서비스를 무중단에 가깝게 안정적으로 운영한 실전 역량을 갖추었습니다.
[데이터 기반의 정량적 진단과 아키텍처 개선으로 동시 접속 부하]
대화형 AI 진단 서비스를 프로덕션에 적용하는 과정에서, 20명이 동시에 접속해 산출물(이미지·캔버스)을 생성할 때 시스템이 급격히 불안정해지는 문제가 발생했습니다. 이미지 생성 요청이 몰리면서 Azure OpenAI에서 429(Rate Limit 초과) 오류가 반복되었고, 대기 요청이 큐에 적체되며 응답 지연과 실패가 속출했습니다. 단순히 동시성을 낮추면 전체 처리량이 떨어지고, 높이면 429가 폭증하는 딜레마 상황이었습니다.
감으로 파라미터를 조정하는 대신, 원인을 정량적으로 규명하기 위해 두 가지 접근을 취했습니다. 첫째, 어드민 화면에 큐 적체량과 429 누적 카운터를 실시간으로 모니터링하는 기능을 구현했습니다. 둘째, 가상의 N명이 동시 요청을 발사하는 합성 부하 테스트 도구를 직접 개발해 동시성 수준별 에러율과 응답 지연을 반복 측정했습니다. 분석 결과, 병목의 핵심은 '이미지 생성 동시 호출 수'와 '버스트 트래픽의 처리 순서'에 있음을 확인했습니다.
이를 해결하기 위해 세 가지 개선책을 동시에 적용했습니다. 첫째, 실측 데이터를 근거로 이미지 생성 동시성을 최적의 수치로 조정하여 429 에러의 급증을 방어했습니다. 둘째, 사용자의 클릭 요청을 최우선으로 두고 나머지는 라운드로빈 방식으로 처리하는 우선순위 큐를 도입해 버스트를 평탄화하고 공정성을 확보했습니다. 셋째, Retry-After 기반 재시도 로직과 대기 시간에 산출물을 미리 만드는 선생성(Pre-commit) 토글을 추가해 체감 지연을 대폭 줄였습니다.
결과적으로 다중 접속 부하 환경에서도 실패 없이 모든 단계가 안정적으로 완주되도록 시스템을 개선했습니다. 이 경험을 통해 성능 문제는 추측이 아닌 '측정 가능한 지표를 만들고 데이터로 최적점을 찾는다'는 원칙의 중요성을 체득했습니다. 아울러 외부 AI 서비스 연동 시 재시도, 큐, 폴백을 조합한 완충 설계가 프로덕션 안정성의 핵심임을 깊이 깨달았습니다.
[엄격한 보안과 설명가능성을 갖춘 금융·보험 생성형 AI 아키텍처 설계 방안]
보험·금융 환경에서 생성형 AI를 운영할 때는 보안·개인정보 보호, 설명가능성, 모델 리스크 관리, 내부통제 및 거버넌스가 가장 중요합니다. 금융 데이터는 고객의 민감한 재무·건강·사고 정보를 포함하고, AI의 판단이 보험금 지급 및 심사 등 핵심 의사결정에 직접적인 영향을 미치므로 일반 서비스보다 훨씬 엄격한 통제가 요구됩니다.
첫째, 보안 및 개인정보 보호를 위해 입력 단계에서 개인정보를 마스킹·비식별화하고 최소 정보만 전달해야 합니다. 저는 과거 서비스 운영 시 개인정보 익명화 배치를 설계하고, 리소스와 키를 분리해 접근을 통제한 경험이 있습니다. 금융 환경에서는 폐쇄망(Private Endpoint) 기반의 사내 LLM 서빙과 로그 암호화가 필수적입니다.
둘째, 설명가능성 확보를 위해 RAG의 출처(Citation)를 답변에 명시하고 참조 문서를 추적 가능하게 만들어야 합니다. 저는 단순 벡터 검색 대신 Neo4j 기반 GraphRAG 및 온톨로지를 활용해 근거 문서와 관계를 함께 반환하도록 설계한 경험이 있으며, 이는 금융 심사 결과의 투명성을 높이는 실질적인 방안이 됩니다.
셋째, 모델 리스크 관리 차원에서는 환각 현상에 대비해 LLM 출력을 구조화된 스키마(Envelope)로 강제 검증하고, 실패 시 규칙 기반 템플릿으로 자동 폴백하는 안전장치를 구현해 운영했습니다. 여기에 금융권은 사람의 검토(Human-in-the-loop) 게이트와 편향 모니터링을 결합해야 합니다.
마지막으로 내부통제 및 거버넌스를 위해, 프롬프트를 카탈로그와 DB 구조로 자산화하여 이력 추적 기반을 다진 경험이 있습니다. 이를 금융 환경에 확장하여 프롬프트·모델·데이터에 대한 권한 분리와 감사 로그, 변경 승인 절차를 제도화함으로써 규제 준수와 운영 안정성을 동시에 달성할 수 있습니다.
